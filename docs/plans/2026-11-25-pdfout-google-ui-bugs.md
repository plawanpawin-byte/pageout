## Global Constraints

- App: D:/Lookout-apps/pdfout (Electron, plain JS, no build step). Renderer: index.html, kit.js (kit copy), lookout.css (shared Google-dark tokens), app.css (98 lines), app.js (1359 lines), x-*.js (batch, convert, doc, pages, secure, util), th.js (Thai font/shaping helpers), i18n.js, extra.js. main.js 149 lines, preload.js 18.
- Privacy: PDFout is fully offline (network kill-switch in main.js + strict CSP: no external fonts/scripts/images). Do not add any network access. Icons: inline SVG only (Material Symbols Outlined path data OK).
- Do not break existing features: open (dialog, drag-drop, Ctrl+O), view/zoom/fit/page nav/thumbnails/outline, annotate (highlight, draw, shapes, text, stamps, notes), Replace text, edit text, forms, signing, OCR, merge/split/extract/rotate/delete/reorder pages, crop, watermark, page numbers, compress, convert (images/Word/etc.), password protect/unlock, redact/sanitize, PDF/A, batch, Thai text (embedded NotoSansThai; the 1.0.20 Thai-save regression must never return), undo/redo (80 steps, picture pool), save/Save as, unsaved-changes guard, EN/Thai UI strings (i18n.js / th.js). Saved PDFs must stay valid and openable in other readers.
- Dark Google theme only, plain English UI text (Thai translations exist: when adding strings add Thai too), no emoji.
- Version: do NOT bump, push or release. Commit on branch google-ui in D:/Lookout-apps/pdfout. PDFout is released as a pre-release (beta) only.
- Test harness: D:/Lookout-apps/_tools/multi-main.js runs the app with a steps file. Pattern (see D:/Lookout-apps/_tools/run-x.sh and run-f.sh):
  `LK_APP=D:/Lookout-apps/pdfout LK_STEPS=D:/Lookout-apps/_tools/<steps>.js LK_LOG=D:/Lookout-apps/_tools/test/out/<name>.log LK_OPEN=<pdf to return from the Open dialog> LK_SAVE=<path returned from Save dialog> LK_FILES=<a|b granted paths> LK_MSGBOX=<n answers message boxes> LK_USERDATA=<fresh dir under D:/Lookout-apps/_tools/test/> timeout 150 D:/Lookout-apps/frameout/node_modules/.bin/electron.cmd D:/Lookout-apps/_tools/multi-main.js` (pdfout has its own node_modules/electron too). Steps: module.exports=[{code,wait,input,shot,save}]; results in <name>.log.res, renderer console in <name>.log. Without LK_SAVE / LK_OPEN a real dialog opens and the run hangs. Fixture PDFs: D:/Lookout-apps/_tools/test/*.pdf (demo, form, rich, rich2, rot, rot90, sample). Existing step files: _tools/st-pdfout*.js, st-pageout0.js and others named *pageout*/*pdfout*; run them all once as a baseline (note which already fail) and keep them green. Never use wildcard rm; use fresh userData dirs; never `git worktree remove --force`.
- Don't kill electron processes you did not start (the Claude desktop app itself is Electron).

Restyle PDFout like Gemini/NotebookLM/Frameout 1.0.31: 56-64px top app bar (mark + name, file name/title, circular 40px icon buttons with tooltips, primary pill Save/Open), rounded 16px panel surfaces with 8px gutters (thumbnail/outline panel left, document stage centre, tool/inspector panel right) with panel headers + collapse buttons, floating toolbar for tools with tonal selected state, Material outline icons, M3 dialogs (28px radius), menus (12px), filled inputs with focus ring, snackbar toasts, a Gemini-style start screen when no document is open (New/Open pill, Recent files list if recent data exists — only use data the app already keeps; do not invent storage), tonal chips for modes. Keep every existing feature reachable (check every button still exists and works) and keyboard accessible. Screenshots: D:/Lookout-apps/_tools/test/out/pdf-gui-*.png (start screen, document open, annotate tools, thumbnails/outline, dialogs, narrow window, Thai UI).

## Task 2: Break-it bug sweep (the main goal)

Try hard to break PDFout and fix every bug found; the owner wants confidence for real use. Use the fixture PDFs plus generated ones (many pages 200+, large 20 MB, tiny, rotated pages, encrypted with user/owner password, corrupt/truncated file, zero-byte file, non-PDF renamed .pdf, Thai text, forms with fields, scanned image-only pages, huge page size, pages with annotations already). Cover: open via dialog/drag-drop/Ctrl+O/recent/command line arg; failing open (bad file, wrong password, cancel); zoom/fit/scroll/page jump extremes; thumbnails; each annotation tool incl. tiny/zero-size drags, undo/redo across everything, delete/move/resize annotations; Replace text + edit text with Thai/long/empty text; forms fill/flatten; sign; OCR; page ops (merge, split, extract, rotate, delete last page, delete all pages, reorder, crop, watermark, page numbers); compress; convert; protect/unlock; redact/sanitize; PDF/A; batch; save, Save as (cancel, existing name, read-only path, unicode path), reopen the saved PDF and verify content/page count/annotations survive; unsaved-changes guard (close, open another, quit); rapid repeated clicks; keyboard shortcuts while typing in inputs; window resize small; menus/dialog Esc/focus; very long names; offline; console errors. Method: for each bug write a harness step that reproduces it (see it fail), fix, see it pass. Add a seeded fuzzer of ~500 mixed actions asserting no console errors and invariants (page count, selection ids exist, undo-all restores the first snapshot, saved PDF reopens). Report unfixed items with repro.
